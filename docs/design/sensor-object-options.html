P&ID front panel · one object system

Front Panel Object System

Sensor, valve and state machine are one construction: a glyph, a name line, a line of live text. Drawn at true size in the app's palette.

OBJECT

Every display permutation

per-object toggles

Glyph, name line, units, decimals and which side the text sits on are independent per-object settings. Flipping the side mirrors the whole block — the bubble moves across and the text right-aligns so it still hugs it — for instruments drawn against the right edge of a panel. Default is right, as it is today.

BUBBLE

Option C — the type, set large

text is editable

Free text on the object, defaulting to the leading letters of the refDes. Size steps down with length; blank draws an empty bubble, so option A is a setting, not a second widget.

The name line is a free-text field too — default is the bound control's refDes, blank is the same as off, and it is not truncated: a longer label makes a wider object.

STATES

Two axes, eight combinations

the whole vocabulary

A data condition — live / nodata / stale / unbound — and an alarm, meaning an alert against the channel or its node that is raised and unacknowledged. There is no range state (out of range is live + alarm) and no offline state (node offline is nodata + alarm). Nothing else can occur.

The body carries a tint as well as the ring: red-ish when alarming, amber-ish when stale. On a panel of thirty objects that shows where the problem is before a reader has picked out which ring changed colour — it is a hue, not a highlight, dark enough that the interior text stays legible.

Resolving the two onto one drawing: an alarm takes the ring's COLOUR outright, so it is never hidden behind an amber stale ring — at the same weight as every other state, because a thicker stroke reads as a different kind of object rather than the same object in trouble; it takes the number only where there is a number to redden; dashed means unbound and nothing else. Selection is a white glow layered underneath, so an alarming object stays red while selected.

VALVE

Symbol and feedback ring

Shut lies across the bore at 45°, open along it, and everything the valve reports lives inside the circle. With both readings in one disc they need to stay separable, and two rules do it. Filled is fact, hollow is intent: a made switch fills, an unmade one outlines, a commanded position is always a hollow ring. And a switch is a pair — one dot at each end of the bore line it reports on, so it reads as that line's endpoints rather than as a mark that happens to sit nearby. The command ring is single and rides between them, so shape alone keeps them apart. Green is earned by the switch, not by the command. Asking for open tells you only that you asked, so a limit-switched body stays grey until the open pair lights — and mid-travel, with neither switch made, grey is simply what is true rather than a special case. Green is also a claim about now, so the data axis outranks all of it: a stale valve asserts nothing. The glyph rotates for top-to-bottom runs — bore and ticks turn together, and a percentage figure stays upright, because a number that has to be read sideways is not a reading.

On a continuously-positioned valve the arc is feedback and the dot is command, both drawn inside the circle so a throttling valve reads as one disc. When they agree the dot caps the arc; when they disagree the gap is the fault.

MACHINE

State ring

The same circle as the sensor bubble — one ring, no segments. It still answers the question that matters, is the machine where it was told to be?, but with a concentric accent ring drawn only while a commanded target is unreached, and the transition spelled out on the text line. Nothing is added to the glyph when there is nothing to say. Abort is an ordinary state — only a raised alert is loud.

The interior mark is a diamond, everywhere. One shape for every state-machine object in the GUI — it does not encode which machine, which node, or which state, because the name line and the ring already carry all three. Several machines can drive channels on one node, and a node holds one locally-loaded state; none of that belongs in a 34 px glyph. The rejected candidates are kept below as the record of what a quieter mark would have cost.

COMMAND

The dropdown, rebuilt

segmented

Today a toggle is four clicks and a mouse race: the panel opens centred on the object, you travel to a small button, and any click outside dismisses it unless you hit Pin first. Same concept, three changes — commands at the top, it opens under the cursor, and the control does not relayout when the state changes, so open, closed, open is three clicks that never move the mouse. The control is a segmented pair: dark is where the valve is, light is what you can do.

Closing. Esc and ✕ both always close it — a close control that sometimes does not close is worse than none. Pin stays, but it governs one thing only: whether clicking off the panel dismisses it. Unpinned, a click on the canvas closes it; pinned, it survives, which is how you keep several panels open at once. Repeat clicks on the control itself never dismiss anything either way, so the three-click toggle does not need the pin.

The state machine gets the same panel instead of the native <select>, with targets blocked by operator from … gating drawn dimmed rather than silently refused by the server.

MARKS

Drawn, not emoji

Replacing _categoryIcon() in alerts.js, which returns system emoji that render differently on every machine. Two marks, because the alert bar renders two severities — stale, offline and unbound are object states carried by the ring, not badges, so they never needed one.

EDITOR

Problem list

one flat list

The editor's warnings button is fed from one place — routingErrors.push in editor.js — so it is a routing list. An unbound binding reaches no list at all today. It becomes a problem list: one flat list, no severities, every row clickable back to the element. A drawing check, not a config check.

ALERTS

One path to red

runtime change
FactTodayAfter
CPT-01 above validMax bad_data from the broker colours the reading; the template separately raises a row One auto-generated sensor alert. The object colours from it.
Commanded open, feedback shut Red ring, indistinguishable from a comms fault Templated valve not responding alert, with the reason in words
Node reconnects on reconnect -> info raises a fresh row Line removed. The disconnect alarm stays raised, and the object stays red, until an operator acks it.

Red persists until the alert is cleared by a person, not by the condition going away. A pressure spike that came back down on its own still leaves the object red, because the thing worth knowing is that it happened. So every auto-generated sensor alert latches, and the alarm axis reads "raised and unacknowledged" rather than "condition currently true".

That turns an earlier note into a requirement. Registry.Clear() does not delete an alert — it sets Acked = true and broadcasts alert_acked, so the server acknowledges on the operator's behalf the moment a condition recovers. That is exactly what must not happen here: it would drop the red the instant the pressure came back into band. Recovery needs a resolved-but-unacked state distinct from acked, and Clear is the wrong verb on every recovery path — reconnect included.

SETTLED

Decisions this page encodes

  • Bubble: option C, interior text editable.
  • Name line is the title, editable, defaults to the refDes.
  • Decimals per object, default 2, display only.
  • Units hidable per object.
  • No range state — out of range is an alarm.
  • No offline state — it is nodata + alarm.
  • Unbound is grey, dashed and italic. Not an alarm.
  • Alarm is ring colour plus a tinted body — normal weight, static, no dot, no pulse.
  • Selection is a glow, layered, not a state.
  • Shut is 45°; feedback gets its own outer ring.
  • Arc is feedback, dot is command.
  • Green follows the data axis, never hardcoded.
  • Mismatch is an alert, not a look.
  • Machine ring is unsegmented; an accent ring means a target is unreached.
  • Machine interior is a diamond, one shape for every machine object.
  • Red latches until a person acks — not until the condition clears.
  • No sparkline, no status dot.
  • The dropdown stays, rebuilt around the click count.
  • Segmented control, light = actionable, dark = current.
  • Esc and ✕ always close; Pin governs click-off only.
  • Positionable valves get presets plus a typed entry.
