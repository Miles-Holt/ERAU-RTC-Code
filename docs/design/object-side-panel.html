GAPS

Problems in the current panel

from the code
  • It never marks its object selected. You asked for exactly this earlier — "is there selected highlighting in the panel too, if I click a sensor to make the right side panel come up". The white selection glow was built for it and is not wired, so with two similar objects nearby there is nothing saying which one you opened.
  • It fails silently. if (!ctrl) return; — right-click an object whose control is not in the config and nothing happens at all. No panel, no message. It is a real case, not a hypothetical: a config key gets renamed or deleted while the panel markup still binds the old one, a copy-pasted panel section brings its controls along without the matching config entries, or a control is only registered under a mode or feature flag while the panel draws it unconditionally. Decided: the runtime may stay silent — the editor catches it instead, warning at load time for every declared control with no config entry, named by id and location.
  • It behaves unlike the command panels. They now close on Esc and stack. This one closes on any right-click anywhere — even a right-click on a different object — and cannot be kept alongside another. Decided: side panels do not pin.
  • It rebuilds on every open. Channels are removed and re-added each time, so the chart starts empty and refills — the history you opened it to see arrives a moment late. Decided: acceptable for now. The refill is only slow because it ships every raw point; the work worth doing is on the wire, not the cache — see 04.
  • The header is thin. refDes and description only: no value, no units, no state, no node.
MENU

Design changes to pick from

reply with numbers
Make it behave like the rest of the panel
01
Glow the object while its panel is open
Wire the existing .selected class when the panel opens, clear it on close.
Already built and already asked for. Nothing else here matters if you cannot tell which object you are looking at.
02
Esc closes it; a right-click elsewhere does not
Esc and ✕ close it. A right-click on another object retargets the panel instead of dismissing it. No pin — side panels stay unpinned.
One set of habits for every panel, rather than two, without adding a pin state to carry around.
03
Catch the missing control in the editor, not at right-click
Leave the runtime silent. At load time walk the panel's declared controls and warn for each key with no config entry, with the control id and where it sits.
The person who can fix a dangling binding is the one editing the drawing, not the operator right-clicking it during a test.
04
Send aggregates, not every point
History for a panel that is 300 px wide does not need one sample per acquisition tick. Downsample server-side into per-bucket min/max/last at the resolution the request asks for, and send that. Raw points only when the window is short enough to want them.
Chosen over caching the chart between opens: the refill is slow because of what crosses the wire, so bucketing fixes the open, the pan, the zoom and the preset switch at once, and it gets cheaper as the buffer gets longer rather than more expensive.
Show what the object is doing
05
Live readings table under the chart
Every channel with its current value, units and per-object decimals — coloured on the same two axes as the object.
The panel currently shows history but not the present.
06
State line in the header
The object's data condition and alarm as a pill: LIVE, STALE, NO DATA, UNBOUND, ALARMING.
Same vocabulary as the glyph, so the panel and the object cannot disagree.
07
Raised alerts for this object, each row opening an alarm panel
List alerts attributed to these channels or their node — rows only, no inline Ack. Clicking a row opens a second right-side panel built from the same template, scoped to the alarm rather than the object: the trend of the channel that tripped it, how long it has been raised, its long description, and Ack / Reset / Suppress. Suppress is rule-level and volatile: the rule stops evaluating until someone unsuppresses it or the control node restarts.
Ack is a decision, and one button on a one-line row is not enough to make it on. The row says something is wrong; the panel behind it is where you find out what and then act.
07a
A long description on the alert definition
Alerts carry a one-line message today, sized for the board. Add an optional long form on the definition — describe "…" alongside message in config/alerts/alerts.alert, same placeholder interpolation — and render it in the alarm panel.
"OV-05 not responding to command" is the right length for a list and the wrong length for deciding what to do about it. The person who wrote the rule knows what it means; this is where they write it down.
07b
Somewhere to see what is suppressed
Filter the alerts list by state — raised, unacknowledged, suppressed, cleared — and keep a suppressed count visible even when the filter is not on it. A suppressed rule keeps its row, greyed, with a Suppressed · until restart pill rather than disappearing from the board.
Rule-level suppression is the one operator action that makes the system stop watching, so the failure mode to design against is a rule suppressed during a hold that nobody remembers before the next run. A count that never hides is what makes "we suppressed three things this morning" recoverable. Restart clearing it is a safe default, but it also means the board can look different after a restart with nobody having touched it — the pill says "until restart" for that reason.
Note: the registry records only acked and resolved — no operator identity, and the browser connects anonymously. So "suppressed by" is not available without adding identity; time-of-suppression is.
08
Which node owns it, and is that node up
"DAQ001 · connected 4m" in the header.
Node offline is half the reason an object goes quiet, and nothing on the panel says which node it was.
09
A channels section on the alert, declaring what its plot draws
Give an alert definition a block saying which channels its panel plots and what reference lines go behind them — line <value-or-channel> "<label>", where the value may be a literal, a channel (so an operator-settable limit moves with it), or a per-channel property. The bad_data template becomes one consumer: it emits two lines at that channel's validMin and validMax. Nothing is drawn on the object panel's plot — only on the alarm's.
Your call, and the right generalisation: the valid band is not a special feature, it is one alert saying what context its plot needs. The same mechanism then covers a rate-of-change limit, a setpoint the reading was supposed to hold, or a companion channel worth seeing beside the one that tripped — without a new rendering path each time. On an object plot a band is decoration on a trace nobody is questioning; on the alarm plot it is the evidence for why the alert exists. Inert until bounds are actually configured — none are today.
alert CHAMBER-HIGH
  if CPT-01 > LIM-CPT01-HIGH

    plot CPT-01
    line LIM-CPT01-HIGH "abort limit"

Click a channel in the readings table to copy its name. The refDes names the object; the channel is what config, alert rules and graph cells actually reference.
Small, and every config edit starts with typing one of these by hand — and typing the wrong one of the two is its own class of bug.

14
Plot the state channel itself, and name the states in the tooltip
Rather than drawing separate transition rules, add SM-<NAME>-STATE to the chart as a step trace — it is already a real channel carrying the state index. The tooltip renders the index through the state_config table, so it reads "autoSequence", not "3".
The single most useful thing on this list during a firing sequence: it puts a reading in the context of what the sequence was doing. Doing it as a channel rather than as annotations means it pans, zooms, buckets and exports like everything else on the chart, and it needs no new message — the index is already in data and the names are already in state_config. The enum-to-name rendering is the only new work.

Command and feedback as a pair
For a valve, draw CMD and FB on one axis, so lag is a visible gap.
Same idea as the dot-versus-arc on the glyph, at history scale.
16
Freeze
A button that stops the window advancing so a reading can be studied without chasing it.
Pan already does this implicitly; a button says so.
